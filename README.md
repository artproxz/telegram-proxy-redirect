# Telegram Proxy Redirect — строгая версия

Минимальное табло рабочих MTProto-прокси для Telegram.

Главный принцип этой версии: **на сайт попадают только прокси, которые прошли 10 TCP-проверок подряд**. Если сервер не прошёл хотя бы одну проверку, он не публикуется в `proxies.json` и не показывается менеджерам.

## Что изменено

- интерфейс стал заметно проще: менеджер видит только рабочие прокси, пинг, статус `10/10` и кнопку подключения;
- удалены лишние панели с технической информацией, поставщиками, поиском и подробной диагностикой;
- `fetch-proxies.js` теперь проверяет каждый кандидат **10 раз подряд** через TCP-connect;
- старый список больше не подставляется, если новые прокси не прошли строгую проверку;
- если железно рабочих серверов нет, сайт показывает пустое состояние, а не сомнительные прокси;
- сайт перечитывает `proxies.json` каждые **10 секунд** и обновляет отображаемый пинг без перезагрузки страницы;
- при клике на прокси карточка тухнет только у конкретного пользователя через `localStorage`;
- новые или обновлённые прокси подсвечиваются и могут вызвать уведомление.

## Важное ограничение

GitHub Pages — это статический сайт. Браузер не умеет делать настоящий TCP-ping до MTProto-сервера. Поэтому настоящий пинг измеряется в GitHub Actions, а сайт каждые 10 секунд перечитывает готовые значения из `proxies.json`.

Это честнее, чем имитировать пинг через `favicon.ico`, `fetch` или WebSocket: такие способы не проверяют MTProto-сервер корректно и могут показывать ложные результаты.

## Как запустить на GitHub

1. Загрузи файлы в репозиторий `telegram-proxy-redirect`.
2. Сделай commit и push в ветку `main`.
3. Открой GitHub → **Actions**.
4. Запусти workflow **Fetch Telegram Proxies** вручную через **Run workflow**.
5. После успешного запуска workflow обновит `proxies.json`.
6. Открой сайт:

```text
https://artproxz.github.io/telegram-proxy-redirect/
```

## Расписание обновлений

GitHub Actions запускается по МСК:

- 08:30
- 12:30
- 16:30
- 20:30
- 22:00

После 22:00 автообновление отключено до 08:30.

## Как работает строгая проверка

Для каждого найденного прокси выполняется серия TCP-подключений:

```text
1/10 → 2/10 → 3/10 → ... → 10/10
```

Прокси публикуется только если все 10 подключений успешны.

В `proxies.json` для каждого опубликованного сервера сохраняется:

- `pingMs` — медианный пинг по 10 успешным проверкам;
- `pingAvgMs` — средний пинг;
- `pingBestMs` — лучший замер;
- `pingWorstMs` — худший замер;
- `strictPassed` — сколько проверок пройдено;
- `strictRequired` — сколько проверок требовалось;
- `checkSamplesMs` — все 10 замеров.

## Настройки в GitHub Actions

В `.github/workflows/update-proxies.yml` используются параметры:

```yaml
MAX_CANDIDATES: 100
MAX_PROXIES: 12
TCP_TIMEOUT_MS: 3000
CHECK_CONCURRENCY: 10
STRICT_CHECKS: 10
STRICT_CHECK_PAUSE_MS: 180
```

Что это значит:

- `MAX_CANDIDATES` — сколько найденных прокси проверять;
- `MAX_PROXIES` — сколько лучших прокси публиковать на сайт;
- `TCP_TIMEOUT_MS` — таймаут одного TCP-подключения;
- `CHECK_CONCURRENCY` — сколько серверов проверять параллельно;
- `STRICT_CHECKS` — сколько успешных проверок подряд требуется;
- `STRICT_CHECK_PAUSE_MS` — пауза между проверками одного сервера.

## Локальный запуск

```bash
python -m http.server 8080
```

Открыть:

```text
http://localhost:8080
```

Для проверки JavaScript-синтаксиса:

```bash
node --check fetch-proxies.js
```

Для ручного запуска парсера:

```bash
node fetch-proxies.js
```

После этого будет обновлён `proxies.json`.
