# Telegram Proxy Redirect — real-check версия

Минималистичное табло рабочих Telegram MTProto-прокси для менеджеров.

Главное отличие этой сборки: **открытый порт больше не считается рабочим прокси**. Перед публикацией сервер проходит настоящую проверку через TDLib: `addProxy + pingProxy`. То есть GitHub Actions проверяет не просто TCP-доступность, а реальную пригодность MTProto-прокси для Telegram.

## Что сделано

- интерфейс очищен до минимума: количество рабочих прокси, время обновления, сервер, порт, пинг, кнопка подключения;
- убраны подробные изменения, технические блоки, провайдеры, статусы `10/10` и лишние анимации;
- оставлена только лёгкая кромка и значок 🔥 для самых быстрых прокси;
- сайт перечитывает `proxies.json` каждые 10 секунд, но не перерисовывает всю страницу без необходимости — карточки не прыгают;
- при клике карточка тухнет только у конкретного пользователя через `localStorage`;
- добавлены более сильные поставщики: GitHub-агрегаторы с автообновлением и крупные Telegram-каналы;
- проверка стала двухступенчатой: сначала быстрый TCP-shortlist, потом реальная TDLib-проверка;
- публикуются только те прокси, которые прошли весь профиль проверки.

## Профиль проверки

По умолчанию один опубликованный прокси должен пройти:

```text
5 TCP-подключений + 5 реальных TDLib pingProxy-проверок = 10/10
```

`pingMs` на сайте — это медиана реальных `pingProxy`-замеров, а не имитация браузером.

## Как запустить на GitHub

1. Загрузи файлы в репозиторий `telegram-proxy-redirect` с заменой старых.
2. Сделай commit и push в ветку `main`.
3. Открой GitHub → **Actions**.
4. Выбери workflow **Fetch Telegram Proxies**.
5. Нажми **Run workflow**.
6. После успешного прогона workflow обновит `proxies.json`.
7. Открой сайт:

```text
https://artproxz.github.io/telegram-proxy-redirect/
```

## Расписание обновлений

GitHub Actions запускается по МСК:

- 08:30
- 12:30
- 16:30
- 20:30
- 22:00

После 22:00 автообновление отключено до 08:30.

## Настройки проверки

В `.github/workflows/update-proxies.yml`:

```yaml
MAX_CANDIDATES: 180
MAX_REAL_CANDIDATES: 32
MAX_PROXIES: 10
TCP_TIMEOUT_MS: 2500
REAL_TIMEOUT_MS: 9000
TCP_CHECKS: 5
REAL_CHECKS: 5
CHECK_CONCURRENCY: 24
```

Что важно:

- `MAX_CANDIDATES` — сколько найденных ссылок взять из источников;
- `MAX_REAL_CANDIDATES` — сколько лучших после первичного TCP-фильтра пустить на тяжёлую TDLib-проверку;
- `MAX_PROXIES` — сколько лучших рабочих серверов показать на сайте;
- `TCP_CHECKS` — количество стабильных TCP-проверок;
- `REAL_CHECKS` — количество реальных проверок Telegram через TDLib;
- `REAL_TIMEOUT_MS` — таймаут одной реальной проверки.

Если GitHub Actions начнёт выполняться слишком долго, уменьшай `MAX_REAL_CANDIDATES` до `20–24`. Если рабочих прокси мало — увеличивай до `40`.

## Локальный запуск

Первичная установка зависимостей:

```bash
npm install
```

Запуск проверки:

```bash
npm run fetch
```

Запуск сайта локально:

```bash
python -m http.server 8080
```

Открыть:

```text
http://localhost:8080
```

Проверка синтаксиса серверного скрипта:

```bash
node --check fetch-proxies.js
```

Для фронта достаточно открыть страницу в браузере и посмотреть консоль разработчика.

## Важное ограничение

GitHub Pages — статический сайт. Он не может сам выполнять TDLib-проверку или TCP-пинг из браузера. Поэтому реальная проверка выполняется в GitHub Actions, а сайт раз в 10 секунд перечитывает уже готовый `proxies.json`.
